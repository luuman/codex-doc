# 核心概念与提示指南

## Codex 的工作方式

Codex 是一个通过提示词（Prompt）驱动的 AI 智能体。你用自然语言描述任务，Codex 会进入一个循环：调用模型、执行操作（读取文件、编辑代码、调用工具），直到任务完成或你取消为止。

---

## 线程（Thread）

**线程**是一次完整的工作会话，包含你的提示词以及随后的模型输出和工具调用记录。

在一个线程中，你可以连续提交多个提示词，例如：
1. 先让 Codex 实现某个功能
2. 再让它为这个功能添加测试

### 本地线程 vs. 云端线程

| 类型 | 运行位置 | 特点 |
|------|----------|------|
| 本地线程 | 你的机器 | 可访问本地文件，在沙箱环境执行命令 |
| 云端线程 | 隔离云环境 | 需要代码托管在 GitHub，适合并行工作或跨设备委托任务 |

---

## 上下文管理

提交提示词时，提供相关上下文可以显著提升效果：

- **文件引用**：直接提及或附加相关文件
- **图像**：截图、设计稿（IDE 插件会自动包含打开的文件和选中的代码范围）

### 自动上下文压缩

对于长任务，Codex 会自动**压缩上下文**——通过摘要方式保留关键信息，使工作可以在不超出模型上下文窗口的情况下持续进行。这使 Codex 能够处理复杂的多步骤项目。

---

## 高效提示技巧

### 1. 包含验证方式

Codex 在能够验证工作结果时，效果最佳。在提示词中提供：

- **复现步骤**：如何触发你描述的问题
- **验证方式**：如何确认功能已正常实现
- **质量检查**：代码规范检查（Lint）或预提交钩子（Pre-commit hooks）

**示例（低效）：**
```
修复登录 Bug
```

**示例（高效）：**
```
修复登录 Bug：
- 复现步骤：输入正确的邮箱和密码后，点击登录按钮，页面没有跳转
- 期望结果：成功登录后跳转到 /dashboard
- 运行 `npm test` 验证测试通过，`npm run lint` 通过代码检查
```

### 2. 拆分复杂任务

Codex 处理多个聚焦的小任务，比处理一个庞大任务效果更好。较小的任务：
- 更容易测试和验证
- 出错时更容易回退
- 提供更清晰的改动边界

**不确定如何拆分？** 让 Codex 先提出执行计划：
```
实现用户认证系统。先给我一个分步计划，不要直接写代码。
```

### 3. 提供充分上下文

- 说明技术栈和框架版本
- 指出相关文件路径
- 描述现有架构约束
- 说明代码风格要求（如有团队规范文档）

### 4. 迭代优化

不需要一次写出完美的提示词。可以：
1. 从大方向开始：`"给这个 API 添加分页功能"`
2. 查看结果，再补充细节：`"好的，现在确保 cursor 是 base64 编码的，并添加 has_next_page 字段"`

## 权限与安全

Codex 的操作权限可以根据场景调整：

- **建议模式（Suggest）**：所有操作都需要你确认
- **自动编辑（Auto-edit）**：自动修改文件，执行命令仍需确认
- **全自动（Full-auto）**：自主执行所有操作（适合已充分测试的自动化场景）

:::caution
在生产环境中谨慎使用全自动模式。建议先在测试分支或带有 Git 检查点的情况下运行。
:::
